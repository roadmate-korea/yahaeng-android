# 야행

밤이 되면 달라지는 길을 차가 먼저 알려 주는 Pleos Connect(Android Automotive) 앱입니다. 현대자동차그룹 차량용 앱 개발 공모전 출품작입니다.

- 밤에만 점멸로 바뀌는 교차로에 다가가면 300m 앞에서 한 번 말합니다. 노란 불이 깜빡이면 서행, 빨간 불이 깜빡이면 정지선에서 일단 멈춤입니다. 가는 방향 앞쪽 교차로만 말하고, 옆 골목이나 지나온 교차로는 말하지 않습니다.
- 밤에 신호등도 조명도 없는 2차로 이상 횡단보도에 시속 30km 넘게 다가가면 150m 앞에서 한 번 말합니다. 밤에는 사람이 늦게 보이기 때문입니다.
- 와이퍼가 계속 도는 밤에는 젖은 노면 기준 속도(제한 속도의 80%)를 "노면이 젖었다면"이라는 조건과 함께 말합니다. 크루즈 목표 속도가 그보다 높으면 그 차이도 말합니다.
- 점멸 교차로에서 실제로 멈췄는지, 횡단보도 앞에서 속도를 줄였는지는 점수가 아니라 사실(가장 낮았던 속도)로 남깁니다.
- 처음 한 번만 열면, 그 뒤로는 차가 켜질 때 저절로 시작됩니다. 앱을 열지 않아도 밤에 운전하면 동작합니다.

기획서는 [docs/기획서.md](docs/기획서.md)에, 화면 설계는 [Figma](https://www.figma.com/design/AtADUpUCbcL3NES6WcRmQL)에 있습니다.

## 왜 필요한가

많은 지자체가 교통량이 적은 밤 시간에 신호등을 점멸로 돌립니다. 운전자는 이 교차로가 몇 시부터 점멸인지 알 수 없고, 신호가 꺼진 것처럼 보이는 교차로를 그대로 지나가기 쉽습니다(도로교통법 시행규칙 별표 2: 황색 점멸은 주의하며 진행, 적색 점멸은 일시정지 후 진행). 비 오는 밤에는 젖은 노면 기준 속도가 따로 있지만(시행규칙 제19조 제2항) 이를 계산해 주는 장치는 차에도 내비에도 없습니다.

규칙만의 문제도 아닙니다. 밤에는 사람이 늦게 보입니다. 신호등도 조명도 없는 횡단보도는 낮에는 평범한 길이지만 밤에는 가장 늦게 알아채는 곳이 되고, 운전자는 어느 횡단보도가 그런 곳인지 미리 알 수 없습니다.

## 화면

| 첫 실행(P에서만) | 점멸 교차로 접근 | 비 오는 밤 |
|---|---|---|
| 위치와 차 속도 권한을 한 번만 묻습니다 | 남은 거리, 할 일, 방향지시등에 따른 한 문장 | 젖은 노면 기준 속도와 크루즈 목표 속도 |

| 내비 위 알림 팝업 | 오늘 밤 기록(P에서만) | 데이터와 설정(P에서만) |
|---|---|---|
| 야행 화면이 없을 때 6초 뜨고 저절로 닫힘 | 교차로와 횡단보도별 가장 낮은 속도와 결과 | 근처 데이터 기준일, 안내 켜고 끄기 |

주행 중(기어가 P가 아님)에는 화면이 읽기 전용입니다. Pleos 창 정책에 맞춰 내비 옆 분할 화면(반쪽)에서도 읽기 쉽게 만들었습니다.

## 쓰는 SDK

모두 공개 Pleos Playground 문서에 있는 API입니다. 외부 서버와 외부 API는 쓰지 않습니다.

| SDK | API | 용도 |
|---|---|---|
| FusedLocation 1.1.3 | `addProximityAlert`, `removeProximityAlert`, 위치 콜백 | 교차로마다 300m(알림), 70m(통과 기록) 근접 알림. 반경 3km 안에서 지금 점멸 중이거나 20분 안에 점멸이 시작될 교차로 12곳까지 걸고, 500m 움직이거나 5분이 지나면 다시 고릅니다. 최근 위치로 진행 방향을 구해(좌우 60도) 앞쪽 교차로와 횡단보도만 알립니다 |
| Vehicle 2.3.2 | TurnSignal, Wiper(스위치, 상태), DrivingMode(크루즈 상태, 목표 속도) | 방향지시등 문장, 젖은 노면 판단, 크루즈 비교 |
| Android Automotive Car API | `GEAR_SELECTION`, `PERF_VEHICLE_SPEED` | 화면 잠금, 정차 요약, 멈춤 기록, 횡단보도 안내 여부(시속 30km 초과) |
| NaviHelper 3.0.5 | `onCurrentRoadSpeedLimit` | 젖은 노면 기준 속도의 바탕 값 |
| TextToSpeech 3.3.1 | ON_DEVICE | 모든 안내 음성 |

일몰과 일출 시각과 진행 방향은 위치와 날짜로 기기 안에서 계산합니다. 내비 경로를 쓰지 않는 이유는 NaviHelper가 경로 선(좌표 목록)을 주지 않기 때문입니다(목적지 좌표와 좌표 없는 회전 안내만 줍니다).

## 데이터

공공데이터포털 [전국신호등표준데이터](https://www.data.go.kr/data/15028198/fileData.do)의 지자체별 파일을 받아 밤에만 점멸하는 교차로만 추려 앱에 넣었습니다(`app/src/main/assets/flashing_signals.csv`, 42개 지역 3,385곳).

- 하루 종일 점멸, 시각 값이 이상한 줄, 한국 범위 밖 좌표는 뺍니다. 같은 운영 시간이고 60m 안에 있는 신호등은 한 교차로로 합칩니다.
- 데이터 기준일이 2025년 이전인 파일은 오래되어 뺍니다. 기준일은 화면에 보여 줍니다.
- 전국 지자체의 약 3분의 1만 파일이 있습니다. 데이터가 없는 곳에서는 없다고 말하고 비 오는 밤 안내만 동작합니다.

```bash
python3 -I tools/signals/fetch.py <받을 폴더>      # 지자체별 파일 받기(보안문자가 뜨면 멈춤)
python3 -I tools/signals/build.py <받은 폴더> app/src/main/assets/flashing_signals.csv
```

공공데이터포털 [전국횡단보도표준데이터](https://www.data.go.kr/data/15028201/fileData.do)의 지자체별 파일에서 보행자신호등유무와 집중조명시설유무가 둘 다 N인 2차로 이상 횡단보도만 추렸습니다(`app/src/main/assets/dark_crosswalks.csv`, 구리시 47곳, 남양주시 449곳).

- 빈칸은 어둡다고 보지 않습니다. 수원시처럼 조명 항목이 빈 지역은 이 안내를 하지 않습니다.
- 20m 안에 여러 줄로 올라온 같은 횡단보도는 하나로 합칩니다.
- 보이는 거리를 숫자로 계산하거나 화면에 띄우지 않습니다. 근거가 공식 시험이 아닌 캠페인 사례뿐이기 때문입니다.

```bash
python3 -I tools/crosswalks/build.py <받은 폴더> app/src/main/assets/dark_crosswalks.csv
python3 -I -m unittest discover -s tools/crosswalks   # 변환 도구 테스트
```

## 대상 사용자와 사업성

| 층 | 누구 | 필요한 순간 |
|---|---|---|
| 전체 사용자 | 밤에 운전하는 모든 운전자 | 앱을 열지 않아도 밤에 운전하면 저절로 동작합니다. 처음 가는 밤길(렌터카, 여행, 이사, 새 직장)에서 가치가 가장 큽니다 |
| 핵심 고객 | 늦은 밤에 정기적으로 운전하는 사람(교대 근무 출퇴근, 학원 픽업, 택시, 새벽 배송) | 점멸 운영 시간(대부분 21~23시 시작, 05~07시 종료)에 매일 운전합니다 |

### 예상 MAU

차가 켜질 때 저절로 시작되므로, 설치한 차 가운데 한 달에 한 번 이상 데이터가 있는 지역에서 밤에 운전한 차를 MAU로 셉니다. 아직 측정한 숫자는 없고, 아래 식의 값은 시범 운영으로 채울 계획입니다.

`MAU = Pleos 탑재 차량 × 데이터 지역 거주 비율 × 밤 운전 비율 × 설치율`

### 리텐션

- 핵심 고객은 점멸 시간에 매일 운전합니다. 같은 길이면 점멸 안내의 새로움은 줄지만, 멈춤 기록과 비 오는 밤 안내, 처음 가는 길의 어두운 횡단보도 안내는 계속 의미가 있습니다.
- 지표는 두 가지입니다. 밤 주행이 있었던 날 가운데 안내가 한 번 이상 나간 날의 비율, 그리고 "그대로 통과" 사실을 들은 뒤 같은 교차로를 다음에 지날 때 멈춘 비율. 두 번째 지표가 행동이 바뀌는지를 보여 줍니다.

### 돈을 내는 주체(모두 가설)

| 주체 | 이유 |
|---|---|
| 현대차그룹 기본 탑재 | 밤 사고를 줄이는 안전 기능으로 차의 가치를 높입니다 |
| 렌터카 회사 | 낯선 밤길을 달리는 손님이 많습니다 |
| 운수회사, 공제조합 | 밤에 일하는 차량의 사고 비용을 줄입니다 |
| 지자체(나중) | 교차로별 실제 서행률은 점멸 운영을 재검토하는 자료가 됩니다. 다만 모으려면 서버가 필요해 이번 범위 밖입니다 |

## 테스트 환경과 필요한 설정

| 항목 | 값 |
|---|---|
| 에뮬레이터 | Pleos Connect Emulator 2.1.0 (`system-images;android-34;pleos_car_emulator;arm64-v8a`) |
| OS | Android 14 (API 34), arm64-v8a. 앱은 minSdk 28, targetSdk 35 |
| 화면 규격 | 2560 x 1440 px, 160 dpi (가로). 야행이 뜨는 앱 영역은 1682 x 1210 px |
| 사용자 | 앱은 Pleos 사용자 10에서 돕니다(`--user 10`) |
| 네트워크 | 필요 없습니다. 데이터는 앱에 들어 있고, 음성 안내(TTS)는 기기 안(ON_DEVICE)에서 만듭니다 |

일반 안드로이드 폰에서는 Pleos 차량 서비스가 없어 동작하지 않습니다.

필요한 설정:

- 처음 실행해 정차(P) 상태에서 [허용하고 시작]을 누르면 위치와 차 속도 권한을 묻습니다. 둘 다 허용해야 모든 기능이 동작합니다. 그 뒤로는 차가 켜질 때(부팅 완료) 화면 없이 저절로 시작됩니다.
- 안내는 해가 진 뒤(위치와 날짜로 계산한 일몰 이후)에만 나옵니다. 점멸 안내는 교차로마다 데이터에 적힌 점멸 시간(대부분 22~23시 이후)에만 나옵니다.
- 기어, 방향지시등, 차 속도, 와이퍼, 크루즈는 Pleos Virtual Console로 바꿉니다. 위치는 `adb emu geo fix <경도> <위도>`로 옮깁니다(FusedLocation이 따라갑니다).
- 기록과 설정은 기어가 P일 때만 열립니다. 화면이 잠겨 있으면 Virtual Console에서 기어를 Park로 바꿉니다.
- 앱 영역을 내비와 나란히 띄우면 반쪽 화면에 맞춘 배치로 보입니다. 야행 화면이 없을 때는 점멸 교차로 알림 팝업이 내비 위에 6초 뜹니다.

## 실행

```bash
adb install -r apk/RoadMate_Yahaeng_release.apk
adb forward tcp:8088 tcp:8088     # Virtual Console: http://127.0.0.1:8088/
```

1. 정차(P)에서 야행을 열고 [허용하고 시작]을 누릅니다.
2. 밤(현지 일몰 뒤, 점멸 장면은 22시 뒤)에 Virtual Console에서 기어를 D, 차 속도를 40으로 둡니다.
3. 구리시 장자대로 89 교차로(22:00~07:00 점멸) 남쪽 700m에서 1초마다 20m씩 북쪽으로 위치를 옮기면, 길 위의 어두운 횡단보도(장자호수길)를 150m 앞에서, 교차로를 300m 앞에서 한 번씩 말합니다(아래 시연 방법의 명령).
4. 교차로를 지나 차 속도를 0으로 두면 지난 사실을 한 번 말하고, 기어를 P로 두면 오늘 밤 요약과 기록 화면을 볼 수 있습니다.
5. 와이퍼를 Low로 두고 10초가 지나면, 내비 제한 속도를 아는 도로에서 젖은 노면 기준 속도를 말합니다(에뮬레이터 내비는 제한 속도 0을 주므로 디버그 빌드의 시연 입력으로 확인합니다).

## 시연 방법

무대는 구리시와 남양주시입니다. 위치는 `adb emu geo fix`로, 차량 신호는 Virtual Console로 넣어 실제 SDK 경로를 탑니다. 에뮬레이터가 주지 않는 두 값만 디버그 빌드의 시연 입력으로 넣습니다.

```bash
# 밤 시각(낮에 찍는 영상용)과 제한 속도(에뮬레이터 내비는 0을 줌)
adb shell am start --user 10 -n com.yahaeng.android/.debug.DemoControlActivity --es time 23:30
adb shell am start --user 10 -n com.yahaeng.android/.debug.DemoControlActivity --ei limit 100
# 구리시 장자대로 89 교차로(22:00~07:00 점멸)로 다가가기
adb emu geo fix 127.14009 37.5831
# 구리시 장자호수길의 신호등과 조명이 없는 횡단보도로 북쪽을 향해 다가가기(1초마다 한 번씩, Virtual Console 차 속도 40)
for m in 300 280 260 240 220 200 180 160 140 120 100 80 60 40 20 0 -20 -40; do
  adb emu geo fix 127.139848 $(python3 -c "print(37.584556 - $m/111195)"); sleep 1
done
```

시연 입력 화면은 디버그 빌드에만 있습니다. release APK에서는 시각과 제한 속도를 바꿀 길이 없어 늘 실제 시각과 내비 값을 씁니다.

## 에뮬레이터에서 확인한 것

- 재부팅하면 부팅 완료 신호를 받아 앱 화면을 열지 않아도 안내 서비스가 시작됩니다.
- 구리시 점멸 교차로 300m 앞에서 근접 알림으로 안내, 좌측 깜빡이를 켜면 좌회전 문장, 시속 40으로 지나간 뒤 정차하면 사실 한 문장, P에서 요약과 기록 화면.
- Virtual Console의 와이퍼 Low와 크루즈 목표 100(27.8 m/s)으로 "노면이 젖었다면 80, 크루즈 100" 안내.
- 내비를 앞에 띄운 채 음성이 계속 나오고, 점멸 알림 팝업이 내비 위에 떴다가 약 6초 뒤 저절로 닫힙니다.
- 구리시 장자대로 89로 북쪽으로 달리면 길 위의 신호등과 조명이 없는 횡단보도(장자호수길)를 150m 앞에서, 점멸 교차로를 300m 앞에서 알리고, 오늘 밤 기록에 교차로와 횡단보도가 함께 남습니다.
- 주변에 다른 교차로가 없는 구리시 점멸 교차로를 동쪽 280m 옆길로 지나면 300m 고리에 들어가도 말하지 않고, 같은 교차로를 정면으로 달리면 300m 앞에서 알립니다.
- 단위 테스트 109개(Kotlin)와 데이터 도구 테스트 6개(Python) 통과.

## 확인하지 못한 것과 한계

- 진행 방향은 최근 위치로 구합니다. 방향을 아직 모를 때(시동 직후 첫 위치) 점멸 교차로는 말하는 편을, 횡단보도는 말하지 않는 편을 고릅니다.
- 횡단보도 데이터는 시연 지역(구리시, 남양주시)부터 넣었습니다. 같은 도구로 다른 지역을 늘릴 수 있습니다.

- 실제 차에서는 시동을 끌 때 절전 상태로 들어가 부팅 신호가 다시 오지 않을 수 있습니다. 그 경우 서비스가 살아 있는지는 실차에서 확인해야 합니다.
- 데이터로는 노란 점멸인지 빨간 점멸인지 알 수 없어 두 경우를 모두 말합니다.
- 앱은 노면을 직접 볼 수 없어 와이퍼가 10초 넘게 계속 도는지로 판단합니다.
- 통과 기록은 메모리에만 두어 앱 프로세스가 끝나면 사라집니다.
- 점멸 교차로를 알린 300m 고리 안이거나 다른 안내를 한 지 30초가 안 됐으면 횡단보도는 말하지 않습니다. 촘촘한 곳에서 일부 횡단보도는 말하지 않고 지나갈 수 있습니다.
